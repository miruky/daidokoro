**レシピを登録して人数に合わせて分量を換算し、複数レシピの材料をまとめた買い物リストを作るアプリ。**

公開ページ: https://miruky.github.io/daidokoro/

## 概要

daidokoroは台所で使うことだけを考えたレシピ帳である。レシピは「材料名 分量」を1行ずつ書くだけで登録でき、詳細画面で人数を増減すると「大さじ1と1/2」「200g」のような日本語の分量表記のまま換算される。料理写真のURLを添えると、一覧のサムネイルと詳細のヘッダーに表示される。今日作るレシピを何品か選ぶと、共通の材料を名寄せして合算した買い物リストができあがり、Markdownとしてコピーまたはダウンロードして持ち出せる。

データはすべてブラウザのlocalStorageに保存され、サーバーには何も送らない。アカウント登録も同期もない代わりに、開いた端末の中だけで完結する。台帳はJSONファイルへ書き出して別の端末へ移したり、バックアップから読み戻したりできる。

### なぜ作ったのか

レシピサイトの分量換算は「2人前」「4人前」の切り替えしかないことが多く、3人前を作りたいときは結局自分で計算することになる。また、複数の料理を1度の買い物でまとめるとき、醤油やみりんのような共通材料を足し合わせる作業は毎回頭の中でやり直しになる。「表記のまま換算する」「材料を名寄せして合算する」という2つの計算を肩代わりするために作った。

## アーキテクチャ

![構成図](docs/architecture.svg)

UI層はフレームワークなしのTypeScriptで、状態が変わるたびに現在の画面を描き直す。分量の解析・換算、レシピ台帳の管理、買い物リストの合算はそれぞれ独立したモジュールで、DOMに依存しないためそのまま単体テストできる。

## 使い方

### 一覧の検索・並び替え・複製

一覧上部の検索でレシピ名や材料名から絞り込める。並び替えは「新しい順」「名前順」「材料の少ない順」から選ぶ。よく似たレシピは、詳細画面の「複製」で材料・手順ごと写しを作り、名前を変えて作り変えられる。

### タグで分類する

編集画面の「タグ」にカンマか空白区切りで言葉を書くと、レシピを「和食」「作り置き」「メイン」のように分類できる。一覧にはタグの絞り込み行が出て、よく使うタグから順に並ぶ。タグを押すとそのタグを持つレシピだけが残り(検索と重ねて使える)、もう一度押すと解除される。詳細画面のタグを押すと、そのタグで絞り込んだ一覧へ移る。絞り込みは材料名と同じく完全一致で、台帳から最後のタグが消えると自動で解除される。

### 分量の換算

材料の分量は表記のまま解析され、人数の比率をかけて再び自然な表記に戻される。2人前のレシピを3人前(1.5倍)にした場合の例:

| 入力           | 出力           |
| :------------- | :------------- |
| `200g`         | `300g`         |
| `大さじ1`      | `大さじ1と1/2` |
| `1/2本`        | `3/4本`        |
| `1個`          | `1と1/2個`     |
| `適量`・`少々` | そのまま       |

gやmlのような連続量は数値で丸め、個数やさじは1/4刻みの分数に寄せる。「適量」「ひとつまみ」のような数えられない表記には手を付けない。

### 買い物リスト

買い物リスト画面で作るレシピと人数を選ぶと、材料名で名寄せして合算する。例えば肉じゃが(醤油 大さじ2)と生姜焼き(醤油 大さじ2)を選ぶと「醤油 大さじ4」になる。単位が揃わない場合は無理に変換せず「200g + 1個」のように併記する。各材料はチェックを付けて買い終えた品を消し込め(打ち消し線になり「残りN品」が更新される)、チェックは端末に保存されるので買い物の途中で閉じても残る。できあがったリストはチェックボックス付きMarkdownとしてコピー・保存できるほか、「印刷」でチェック欄付きの紙に出せる。レシピの詳細画面にも「印刷」があり、材料表と手順だけを台所向けに刷れる。

塩・砂糖・醤油のようにいつも家にある材料は、各行末の壺アイコンから「常備品」にできる。常備品にした材料は買い物リストの本体から外れ、リスト下部の「常備品」にまとまるので、毎回買わなくてよい品で買い物リストが膨らまない。常備品の判定は材料名で行い、別のレシピで同じ名前の材料が出てきても自動で外す。チェックと同じく端末に保存され、「戻す」でいつでもリストへ戻せる。Markdown・印刷・残数の集計も常備品を除いた品目だけを対象にする。

```markdown
# 買い物リスト

- [ ] じゃがいも 3個
- [ ] 醤油 大さじ4
- [ ] 豚ロース薄切り肉 300g
```

### 写真

レシピ編集画面の「写真URL」に画像のURLを貼ると、入力中にプレビューが出て、保存後は一覧のサムネイルと詳細画面のヘッダーに表示される。受け付けるのは `http(s)` のURLだけで、画像のバイナリはリポジトリにもlocalStorageにも溜め込まずに参照する。`images.unsplash.com` と `picsum.photos` のURLは、表示サイズに合わせて幅と切り抜きを補い、`srcset` で解像度に応じた画像を読み込む。

### 書き出し・読み込み

一覧の下の「レシピを書き出す」で、台帳全体を版番号つきのJSONファイル(`daidokoro-recipes-YYYYMMDD.json`)としてダウンロードできる。「読み込む」で別の端末やバックアップから取り込むと、IDが同じレシピは更新日時の新しい方を残し、知らないレシピを追加する形で統合する。書き出したファイルそのものでも、レシピの配列だけのJSONでも読み込める。

### キーボードショートカット

マウスを使わずに主要な操作へ移れる。ヘッダー右のキーボードアイコン、または `?` で一覧を開く。

| キー      | 動作               |
| :-------- | :----------------- |
| `/`       | 検索へ移動         |
| `n`       | 新しいレシピ       |
| `g` → `l` | レシピ一覧へ       |
| `g` → `s` | 買い物リストへ     |
| `?`       | ショートカット一覧 |

入力欄にカーソルがある間は文字入力を優先して発火しない。修飾キー(Ctrl・Cmd・Alt)を伴う場合もブラウザの既定に譲る。

### 制約

- 名寄せは材料名の完全一致で行う。「ねぎ」と「長ねぎ」は別の品目になる。
- 「大さじ」と「ml」のような単位間の換算はしない(併記に留める)。
- データは端末のブラウザに保存されるため、端末をまたいだ同期はできない。

## プロジェクト構成

- `index.html` — エントリポイント
- `src/main.ts` — 起動。ストアの初期化と初回の見本データ投入
- `src/app.ts` — 画面の描画と遷移(一覧・詳細・編集・買い物リスト)
- `src/icons.ts` — 線画SVGアイコン
- `src/style.css` — デザイントークンとスタイル(ライト・ダーク対応)
- `src/lib/quantity.ts` — 分量表記の解析・換算・整形
- `src/lib/recipes.ts` — レシピの型・検証・行形式の取り込み・永続化
- `src/lib/shopping.ts` — 材料の名寄せ・合算、残数の集計とMarkdown出力
- `src/lib/checklist.ts` — 買い物リストで買った材料(チェック状態)の保存・復元
- `src/lib/pantry.ts` — 常備品(買い物リストから外す材料)の保存・復元
- `src/lib/keyboard.ts` — キーボードショートカットの解決(押されたキーから操作への対応)
- `src/lib/image.ts` — 写真URLの検証とレスポンシブな配信URL生成
- `src/lib/backup.ts` — レシピ台帳のJSON書き出し・読み込みと統合
- `src/lib/route.ts` — ハッシュルーティング
- `src/lib/seed.ts` — 初回起動時の見本レシピ
- `docs/architecture.svg` — 構成図
- `.github/workflows/` — CI(lint・テスト・ビルド)とPagesデプロイ

## はじめ方

- Node.js 22以上

```bash
git clone https://github.com/miruky/daidokoro.git
cd daidokoro
npm install
npm run dev
```

```bash
npm test
```

```bash
npm run lint
```

```bash
npm run build
```

## 設計方針

- **ローカルファースト** — 保存先はlocalStorageだけで、ネットワークを一切使わない。台所でスマートフォンを開いたとき、電波に関係なく即座に表示される。
- **表記を壊さない換算** — 分量を数値に正規化して持つのではなく、入力された表記のまま保存し、表示の瞬間に換算する。元のレシピの「大さじ2」が「30ml」に化けることはない。
- **ロジックとDOMの分離** — 換算・名寄せ・検証・ルーティングはすべて純粋関数で、Node環境のVitestでテストする。UI層は描画と入力の受け渡しに徹する。
- **壊れた保存データを握りつぶさない設計** — localStorageの復元時は要素単位で検証し、形の崩れた要素だけを読み飛ばす。1件の破損で全件が消えることはない。後から足した写真URLのような任意項目は、欠けていても妥当なデータとして読む。
- **写真は持たずに参照する** — 画像はバイナリを抱えずURLでホットリンクし、`http(s)` 以外のURLは受け付けない。表示サイズに合わせて配信幅を絞り、レイアウトのずれを防ぐ寸法属性と遅延読み込みを添える。
